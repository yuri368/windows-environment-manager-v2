# V3 UI 与交互整体检查

本轮审查覆盖现有全部页面，保留已认可的紧凑布局、元素颜色和状态标签。范围为浏览器会话内的演示；不接入 Windows、不修改 Python 核心模型。

## 已修正的可复现问题

- 搜索只显示 Java 时，“全选”原来勾选全部 13 个应用。改为“全选可见”，按搜索和状态过滤选取；已有隐藏勾选保留，并显示隐藏数量。预览仍明确展示最终操作范围。
- 撤销菜单关闭后焦点原来留在隐藏选项。方案和撤销菜单统一支持方向键、Home/End、Escape，开关同步展开状态，关闭时返回入口。
- 来源选择器获得焦点时，对照区原来仍显示上一变量。输入框和选择器现在共同更新当前变量。
- “仅看未匹配”在编辑后未重新过滤。输入过程中保留正在编辑的行，完成编辑的 change 事件才移除已经匹配的行，并返回过滤控件焦点。
- 页面切换后焦点原来落到 BODY。主导航、返回工作台与配置入口保留明确焦点和当前页面状态；筛选按钮提供按下状态，配置禁用字段有对应标签。
- 应用行原来的按钮角色包含复选框。改为相邻的原生查看按钮和批量复选框，保持相同布局与点击用途。
- 空自定义值切换来源后原来被覆盖。未初始化值使用 null，与用户输入的空字符串区分。
- 追加预览原来过滤掉实际值中的空元素、移动已有匹配项，并可能给带空白的已匹配项制造重复。经架构讨论确认，演示追加只补缺失非空目标，比较沿用 trim 和大小写敏感，保留实际原文、重复、空项及顺序；前置插入缺失项到头部，后置插入尾部。目标重复不触发数量补齐。replace、whole 与自定义排序确认限制保持原样。
- 行撤销按钮改为“撤销预览”，注明不恢复当前输入；配置说明明确默认来源会跟随配置默认值，其他来源保持其选定值。

## 尚未完成的浏览器视觉验收

浏览器工具曾明确拒绝本地 file 页面访问，本轮没有使用另一路由绕过。实际浏览器排版、原生键盘激活、原生滚动和缩放仍待验收；JSDOM 事件与 CSS 源码不能证明这些结果。

在 1360×680、1112×556 及较窄窗口，需查看应用查看按钮是否与复选框对齐、隐藏选择计数是否换行合理、三个配置列表标题是否可见、历史展开后是否拥挤，以及元素长路径/多状态/待追加按钮是否完整。按 Tab 切换页面与菜单，确认焦点可见且不进入隐藏项。

演示页面刷新会重置会话；历史不持久化。撤销和自定义排序确认仍保留已有演示限制，未声称正式业务功能完整。
