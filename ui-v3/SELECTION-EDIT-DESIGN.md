# V3 选定值增删计划实施说明

本轮依据 docs/architecture/V3_SELECTION_DIFF_V3_2.txt；它覆盖 V3.1 中普通选定值编辑只追加的规则。本轮仍仅浏览器演示。开发和 HTTP 主目录保持原项目目录，ui-v3 为 Git 镜像。

## 单一事实和计划

沿用 DemoPlan。首次真正修改列表选定值之前，captureBaseline 保存只读目标、原选定值、Actual exists/raw/type/revision 和匹配候选位置。连续输入、暂时清空、渲染、取消预览均不刷新基线。

build 在有效基线下计算独立 REMOVE 和 ADD，不猜测替换关系。原匹配且已不再需要的非空元素只有在 Actual occurrence 唯一、未被其他有效选定方案保护时才能删除。Actual 重复值保留并提示“存在重复，删除需确认”；共享值保留并注明原因。未关联 Actual 的空项、原文和相对顺序保持。ADD 沿用 trim 后区分大小写的存在式比较，重复目标各计比例、实际缺失项仅首次追加。

没有编辑基线的普通 append 继续只补缺项。replace/special 继续整值处理。Windows 元素编辑器保留显式稳定 ID 的 REPLACE/MOVE，不与普通文本输入的增删混淆。

## 消费与生命周期

工作台缓存计划，当前选定值、Actual 标记、删增候选、预览和历史读取同一计划。删除-only 不再被摘要误写为整体替换；新 Desired 已匹配也可以同时存在待删除操作。

recordsFor 按 scope/canonicalName 合并同一目标，从同一 Actual 快照计算唯一最终结果。所有参与目标的当前 Desired 参与共享保护；同一 ADD/REMOVE 只出现一次。批量继续按现有 request 顺序处理前置/后置；replace 与 append 混合或不同 whole 目标冲突时禁止确认，append 自定义排序限制保持。

取消预览保留编辑基线。恢复编辑返回编辑前选定值并清除基线；成功应用更新保存选定值后清除基线。浏览应用/方案保留各变量自己的草稿。来源切换和配置 scope/mode/special 变更结束旧编辑上下文；默认来源的默认值编辑从首次变化前捕获基线。

相关 exists/raw/type/revision 变化禁止旧基线产生执行操作，保留输入并展示原/新快照。用户通过“重新检测编辑基线”确认后，以原 Selected 在新快照的匹配范围重建，再重新预览。无关目标变化允许。预览确认也核对基线、参与选定状态及同目标共享保护输入，避免保护关系在预览后变化。

## 元素编辑器

候选保持只读；减号仅按 originalRows 对应稳定 ID 从本次 live rows 移除确定候选，加号按当前方案位置加入。既不自动采纳候选，也不在点击按钮时修改页面快照。候选随实时列表刷新，已删除或已明确改值的原行不再显示旧删除候选。取消不写；显式确认编辑会改变相关 Actual，因此旧 Selected 基线随后失效。

## 验证边界

14 组 Node/JSDOM 检查共 279 项全部通过，其中新增 28 项纯基线/批量检查和 16 项完整流程检查。原有测试中被新契约覆盖的追加-only、同目标逐次历史和显示选择器预期已经同步修订。

实际 Chrome 走通 Maven bin→bin1 的待删除/待追加、编辑器单项采纳与取消、预览焦点循环/Escape、确认后的前后值与历史；另验证 Actual 改变后的显式重建和重复 occurrence 保留。浏览器验收截图和测试报告在 design-evidence/matched-selection-diff-2026-10-13/。

共享保护只基于本演示管理的有效选定方案，不声称掌握机器上所有软件的元素归属。当前不访问真实注册表、不迁移 V2、不合并 main、不发布安装包。
