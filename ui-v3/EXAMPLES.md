# 演示配置体验指南

当前共有 **13 个应用、23 个方案、60 条方案变量记录**。原有 Java、Python、Maven、Hadoop、Scala、Git、VSCode 保留；以下 6 个应用用于体验更多 UI 状态。路径、版本和快照均为虚构示例，不读取本机配置。

在工作台左侧搜索示例名称即可定位。点击应用行查看详情，勾选框用于批量预览；右上方切换准备方案不会直接应用。每个新增示例的详情标题下也有简短说明。

| 示例 | 建议操作 | 可以观察的状态 |
| --- | --- | --- |
| Node.js | 为 NODE_HOME 依次选择“候选值 1 / 2”和“已保存值”，再切换三个方案 | 多来源值、独立方案待应用输入、完全匹配与不匹配 |
| .NET SDK | 切换“日常开发 / 构建服务器”，检查变量作用域，打开预览后取消 | 用户与系统作用域、部分匹配、预览范围 |
| CUDA Toolkit | 比较“GPU 开发 / 兼容工具链”；选择 Path，再点“编辑元素” | 最近应用与准备方案的区别、系统 Path、重复项和空项 |
| 中文长路径工具链 | 查看六条变量；打开配置编辑器，选择“全部方案”并点击另一方案的变量 | 长中文路径、空格与引号、表格和属性区、方案归属 |
| 列表与空值 | 双击 DEMO_SEARCH_PATH，查看和调整列表；再查看 EMPTY / UNSET 变量 | 重复元素、空元素、空字符串与不存在的区别 |
| 共享变量冲突示例 | 同时勾选它与 Node.js，点击批量预览 | 同名变量目标值冲突提示、确认按钮禁用 |

## 推荐先体验的四条流程

1. **值来源和方案切换**：搜索 Node.js → 点击应用 → 把 NODE_HOME 选为候选值 2 → 切到“实验版本” → 再切回“团队默认”。候选值 2 保留在该方案自己的待应用输入中。
2. **列表编辑**：搜索“列表与空值” → 双击 Windows 对照值 → 编辑、上移、删除或新增 → 点“还原本次编辑”。原始空项和重复项会回来。点“应用（演示）”只更新页面快照；取消修改则丢弃弹窗修改。
3. **配置属性和差异**：打开配置编辑器 → 选择“中文长路径工具链” → 选择一个变量 → 修改作用域、模式或默认值 → 打开“修改差异”。然后“还原配置修改”，属性修改数归零，页面环境快照不会被还原。
4. **批量冲突**：先恢复 Node.js 的 NODE_HOME 来源为默认值，再勾选 Node.js 与“共享变量冲突示例” → 批量预览。二者分别准备 C: 和 D: 的 NODE_HOME，因此确认禁用。

## 已明确保留的原型限制

- 含分号的 NODE_OPTIONS、TEAM_BUILD_FLAGS 和 DEMO_COMMAND 被标记为整体处理，元素编辑器不拆分它们。
- “列表与空值 / 自定义排序预览”用于展示 `append` 排序模式；原型仍禁用该模式的模拟确认，不伪造完整排序流程。
- 撤销需要正式操作日志，原型仍只展示操作范围。
- 刷新页面或点击“重置演示”恢复整套初始示例。示例 TOML 可导出，但不是正式后端配置格式。
- 浏览器视觉、DPI 与原生鼠标拖拽仍需实际查看；自动检查仅验证演示数据和 DOM 交互。
