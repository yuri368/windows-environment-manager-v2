# 下一阶段 UI 计划：让值对照进入第一屏

**状态：下一阶段建议，待负责人审阅，未实施。** 2026-10-16。范围仅为 V3 浏览器演示的展示与交互反馈。

推荐先做**工作台核对区与 Windows 当前值表的局部紧凑化**，再处理预览和历史的阅读层级。不是沿用旧方案 P1 的全站按钮、渐变清理：当前最值得解决的是有用内容被上方层级挤出视口，而非颜色不够统一。配置新增 P0 已完成，保留四类就地创建、唯一草稿、单一属性区和原子提交。

## 当前证据与判断

已阅读旧方案、最新实施记录、DESIGN.md、架构 README 及 Windows 快照、执行前审阅、无缝刷新、历史联动契约；查看当前源码。用图片查看工具检查本轮 `design-evidence/astra-next-plan-2026-10-16/` 四张 `*-current.png`，实际 CSS 视口为 1383×851。

- 工作台：Hadoop 两变量、Path 自定义输入状态下，应用概览、变量表、对照标题和审阅提示依次占高；“Windows 当前值／应用后的值”到约 y=750 才出现，首屏主要看见了选定值，尚不能完成三值核对。
- Windows 页：单值也套在整列灰底容器内，再套元素铭牌；7 条记录已接近首屏底部。这里需要提高扫描效率，不能再新增快照层、方案状态或大卡片。
- 预览：已有可用的固定标题、页脚和目标定位。当前正常状态重复出现“2 个目标”与“有实际变更”，摘要占高，但其确认安全信息比装饰重要，放第二阶段精简。
- 历史：新图仅含初始化记录，不能据此判定缺少详情。旧 `ui-history-linkage-2026-10-15/history-linked-desktop.png` 显示已有前后元素联动；详情位于第三列，左侧时间和操作列长期占宽，可作为后续阅读布局依据，实施前补拍当前详情。

三技能分工：Impeccable 的 shape/distill/operate 用于任务顺序、减重复与工具密度；不重跑本会话 context。Taste v2 明确不适用于应用屏幕，只借真实内容、具体构图和看图批判，不采用营销 hero、照片、随机方向或动效数量门槛。Kill AI Slop 延用上轮扫描，针对当前代码分诊：普通容器装饰可减，元素身份、空项、重复与变更状态必须保留；不以扫描数量衡量质量。

## 第一阶段：工作台与 Windows，首轮实施仅到这里

**工作台最小修改点：** `temp.html` 的 `renderOverview()`、`renderRows()`、`renderInspector()`、`inspectReviewMarkup()`；`ui-polish.css` 的 `.overview`；`surface-ui.css` 的 `.inspect-review`、`.inspect-variable`；必要时局部覆盖 `shell-ui.css` 的概览和对照标题背景。保留 DOM 标识和现有事件入口，不调整侧栏批量选择结构。

```text
Hadoop  Windows·未匹配 0/2        准备方案 [2.9.2 ▾]
最近应用：无   默认：2.9.2   有待应用修改
变量表：名称 / 作用域·模式 / 来源 / 当前选定值 / 检测 / 操作
Windows 值对照 · Path   有实际变更       查看方案预览 →
当前选定值 [原文元素…]                         恢复编辑
Windows 当前值 [原文元素…] | 应用后的值·尚未应用 [元素…]
```

删除重复的“应用 / Hadoop”前缀，概览内边距从上下 20px 起调至 12px；应用名保留明确标题，方案选择器与标题同排，最近应用、默认方案和待应用状态各保留一次。桌面变量名称与“查看对照”同行，点击面积至少 28px，辅助文字升至 12px，不靠当前 10.5px 小字省空间。常规变量行以 44–48px 为起点，textarea 按内容增长，长值不得限高裁掉。

将 `#inspectReview` 的正常结果摘要并入对照标题行，保留“查看方案预览”入口和真实请求范围。没有变化、未解决删除、上下文冲突、刷新提示仍明确显示；后两类使用标题下独立提示行，不压进省略号。移除正常状态同时表达“有实际变更／实际变更待确认”的重复文案；保留“尚未应用”。选定值下的作用域、模式、来源并入其标题辅助区域，减少一行空耗。三值内容不折叠、不增独立滚动区；保持选定值在上、当前与结果在下的两列结构，窄屏按此顺序堆叠。

**Windows 最小修改点：** `renderWindows()` 与 `surface-ui.css` 的 `.windows-current`、`.windows-actions`、页面内表格行样式。删除当前值外层灰底框的常驻底色、边框与多余内边距，保留每个可交互元素铭牌、整行分隔及 focus-within 提示。普通单值行目标 42–48px；多元素按内容自然增高，行上下 8px、铭牌行距 5–6px。编辑、原文使用常驻文字动作，28–30px 点击高度，无常驻大描边；原文展开仍留在本行，不增加第二份默认可见值。

共同规格沿用系统字体、纸白与森林绿，正文 13px、值 12–12.5px、关键辅助信息至少 12px。圆角和描边仅服务控件、焦点与元素状态。首轮不重写全局 `.btn`、`.value-stream` 或铭牌生成器，避免波及配置、预览和历史；不清理全站渐变与匹配进度图。

**动作与验收：** 选择 Hadoop → 聚焦 Path → 输入 `%HADOOP_HOME%\bin;;%HADOOP_HOME%\bin; H:\开发工具\长目录 ;` → 查看三值 → 悬停重复项 → 键盘定位 → 打开预览再取消。首屏应同时看见三块标题及至少一行当前值和结果；完整长值允许页面滚动。这是同一数据、同一视口下的视觉目标，不是固定高度限制。切换变量不改输入、勾选或请求范围；点击查看对照只定位，不充当确认。

Windows 页检查 System PATH 中两个 `C:\Windows\System32`、空元素、User 空字符串、Special `cmd /c "echo alpha;beta"` 与长路径。Tab 进入值流，方向键/Home/End 定位，Enter 打开对应 occurrence；删除一项→恢复→取消，快照不变；另一次确认只产生实际编辑记录。保留恢复原 ID 和当前位置、删除时草稿，以及原文 CRLF/CR/LF。缺失变量与存在空值不能合并成同一空态。

联动沿用 `WindowsElements.bindComparison()` 与既有身份键：当前触碰为主，确有身份关联的同项前后用实线，仅同值用虚线；移出恢复键盘焦点关系，不用文本猜 ID。Windows 单页不加入方案匹配或跨快照身份推断。当前值来自最新模拟快照，选定值来自用户输入，应用后的值只消费冻结 plan.after；追加规则对重复与空选定元素的处理不得被“原文保真”名义改写。

动效仅保留定位和状态变化反馈，普通 hover/focus 120–160ms，不让输入导致整区重入场。reduced-motion 关闭移动与顺滑滚动，焦点和状态文字同步保留。不要把跨区连线、鼠标跟随浮框或连续闪烁作为本轮成果。

## 第二阶段：预览与历史的阅读整理，另行推进

预览改 `reviewSummaryMarkup()`、`previewRowMarkup()` 及 `.review-summary/.review-metrics`。正常状态合成一条紧凑摘要：“2 个目标 · 2 个有实际变更 · 尚未应用”；目标导航、作用域、来源及前后元素保留。联动图例在弹窗内显示一次，完整原文仍按目标展开。未解决删除原因、部分完成、无操作、冲突和排序未实现的说明不能随正常摘要一起删掉；刷新版本和再次审阅按钮仍显著。

验收序列：预览→目标定位→展开原文→相关快照变化→保留位置并显示新版→单独重新核对→确认；取消始终保留输入。只有 body 滚动，600px 前后值堆叠，键盘可达固定页脚。任何定位、展开和焦点变化都不算审阅；不触碰 `refreshPreview()`、`confirmPreview()` 的版本绑定和同步验证提交边界。尺寸沿用首轮字体，摘要上下内距 8px 起调；不用飞入或逐项重播。

历史改 `renderHistory()`、`historyChangeMarkup()` 与 `.history-details/.history-detail-body`：保留紧凑记录摘要，展开详情占记录全宽，让前后值与现有变更表对齐；实现仅调整记录展示容器和 CSS，不改变 history 数据结构。取消装饰性时间点光晕，保留时间、操作、来源和部分完成事实。原文按需展开，空白初始页不填假统计或引导卡片。

验收一次真实演示编辑的新增、删除、替换兼移动→展开历史→Tab 进入前后流及明细→方向键联动→收起后焦点回摘要。历史只在本次变更内按既有 audit elementId 对应；没有审计的记录不造关联。删除项只在 Before，新增项只在 After，历史永远是记录快照。窄屏前后堆叠，展开不逐条播放动画，reduced-motion 立即呈现。

## 第三阶段：收尾验收，不再改造配置新增

对 `config-editor.js/css` 的现有四类新增，只补真实中文 IME、200% 浏览器缩放和负责人手感验收；除验收暴露具体问题，不增加设计修改。检查草稿挂起后继续、取消焦点、同名双作用域和候选空值。TOML 展示与导出样式不在本计划内。

每阶段使用相同真实样例，在 1383×851、约 800px、600px 和真实 200% 缩放批量看一轮；修正后最多确认一轮。分别记录视觉、键盘、原文和逻辑结果；仅运行受改动影响的既有专项与必要回归，不把 DOM 通过当美观验收。

本计划不改 DemoPlan、匹配、删除资格、审计、确认规则、真实 Registry 或架构契约，不引入框架和依赖。旧实施记录中的 33 脚本 exit 0、创建 26/26、编辑 14/14 是上轮证据，本轮未重跑。新图没有验收真实 IME、200%、历史修改详情或最终审美；旧截图只证明曾有相应画面。当前无需新增产品决策，负责人只需审阅是否按第一阶段的有限范围推进；本文件不构成实施完成或批准。
