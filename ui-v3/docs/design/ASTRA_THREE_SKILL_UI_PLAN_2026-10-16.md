## 四种新增流程

**变量：名称是唯一必填项。** 点击后入口成为一个带可见标签的名称输入和“创建／取消”，焦点进入名称；默认 User、replace、空默认值。正常属性区临时承接该待建变量的作用域与模式，可选调整仍在原位置；默认值、候选内容创建后出现，不显示一片 disabled 大表单。名称 Enter 或点击创建执行一次完整校验，通过后原子提交、选中新变量并聚焦默认值。创建行消失，成功只在现有状态栏报告。

这也保留同名 System 变量路径：如果 User 下已有该名称，就地显示“用户作用域已有此变量；可在下方改为系统”，并提供“定位作用域”文字动作；聚焦正常作用域控件，用户显式选择 System 后再次创建，不自动切换、不偷加后缀。同目标已有 Special 时沿用既有推断，模式保持 replace 并就地解释禁用原因；不得悄悄解除约束。

**应用：三个名称，一次创建。** 侧栏应用组标题下出现应用名、首方案名、首变量名三个紧凑标签输入行；首项聚焦，Tab 顺序向下，底部创建／取消。正常属性位置用于首变量可选的作用域和模式。首方案必须填写，提交后成为默认方案；首变量必须填写，不生成占位节点。成功选中新应用、方案、变量并聚焦默认值。侧栏可局部滚动，操作行可见，不占据整个主区顶端。

**方案：两个名称，一次创建。** 在当前应用的方案组就地填写方案名和首变量名；其余同应用流程，成功不改变原默认方案。应用不存在时不展示可误触的方案入口，保留新增应用入口；零变量空态仍提供新增变量。现有合法数据不会创建空应用或空方案，空态属于防止界面失去操作入口，不能绕过原子约束。

**候选：新增一行，标签和值分开。** 点击后表格末尾出现临时行，焦点到标签，完整值可以是空字符串；末列为“添加／取消”。完成标签与值后点击添加，校验通过才进入实际候选列表。显示名称不能为空；标签、完整值分别按原文判重，值禁止 NUL 且遵守现有长度限制（`config-format.js:30`–`:36`）。保留值中的分号、重复元素、空元素和首尾空格；“候选整值重复”与“值内部元素重复”是不同规则。

已有候选继续直接编辑，不再给每行增加保存栏。上移、下移、删除常驻文字操作；首尾排序按钮禁用。移动后焦点跟随移动的行；删除后聚焦下一行标签，末行删除则返回新增入口。保留现有来源语义：改选中候选的值同步当前选定值，改标签只改显示，移动跟随原候选，删除选中候选回到默认值（`temp.html:683`–`:694`）。已有编辑没有单独取消承诺，仍使用“还原配置修改”；临时新增行才有取消。

## 未提交状态、校验与键盘

创建状态只保存入口类型、所属对象引用、名称文本、可选 scope/mode 和焦点位置；复用现有创建回调，不建立另一套业务对象模型。输入名称、切换作用域、切走、取消、校验失败均不先写 apps、不增配置差异、不改变运行值、快照或历史。尤其不得采用“先创建再删除”模拟取消。原子提交后才切入真实配置编辑。

同一时刻只保留一份未提交新增草稿。切换应用、方案、变量、配置视图或页面时挂起该草稿，回到原所属位置可见“继续新增”；不自动提交，不迁移到新的父节点。请求另一个新增时，在发起处提供“继续填写／放弃并新建”，避免无声覆盖。全局重置、还原配置明确清除创建草稿；无效父引用只能取消或重新选择。

名称沿用当前精确去重与 V2 变量规范比较，不 trim 后存储。错误放在当前输入行下预留的单行区域，采用“字段：原因”，不新增整页警告框；长对象名不拼进错误，多个错误先显示首项，修正后推进。完整错误可通过焦点读取，窄屏只在局部必要换行。外部已有配置错误导致完整校验失败时标明归属并提供定位，不把它说成当前名称错误。

单行名称 Enter 提交；候选 textarea 的 Enter 插入换行，添加使用按钮或 Ctrl+Enter。输入法组合期间 Enter/Esc 均交给 IME，不触发创建、取消或导航。Esc 仅取消当前临时新增，恢复入口焦点与原选中对象；普通已提交字段不伪装成可回滚输入。Tab 可离开行，不设焦点陷阱。重复点击提交只处理一次；真正执行期间禁用提交，空字段仍允许点击后获得具体错误。禁用状态保留文字对比与可读原因，焦点不能落到消失节点。

## 联动、动效与后续范围

保留触碰起点、同 occurrence ID、仅原文同值三种独立关系，身份实线优先于重复虚线；移出恢复焦点关系，不根据相同文字猜 ID，不添加跟随鼠标浮框。已有 `is-link-source` 等样式与刷新补充属于现状，不把曾报告的问题当作未修复缺陷。Windows 页继续只展示快照；预览只消费冻结 plan，刷新后仍独立审阅再确认，展示定位不算确认。

新增行展开用一次 120–160ms 淡入，输入立即可用；成功用新条目一次短暂底色提示，选择保持静态边线。候选排序只提示落位，错误不抖动、不自动消失；不逐字重播、不让整页平移。reduced-motion 下取消动画和顺滑滚动，保留相同位置、状态文字与焦点。现有跨页动效不在 P0 统一重写。

实施分两阶段：P0 仅修改配置展示与必要的创建状态接线，完成四种入口、原子提交、草稿保留、校验和键盘；涉及 `config-editor.js/css` 与 `temp.html` 的绑定，不改 DemoPlan、匹配、稳定 ID、原文序列化、Audit 或确认绑定。P1 需另行确认，仅统一工作台/Windows/预览/历史的文字动作规格、删重复说明、收敛上述四处渐变；保留各页信息结构与既有状态，不扩成整站重构。

验收用真实数据完成：新增 Rust 工具链→稳定版→RUST_HOME；同名 User/System；新方案不改变默认；候选空值、重复校验、改值调序删除；取消/切走/失败无配置节点；导出和还原保持原语义。逻辑检查应覆盖 IME、原文换行、来源跟随和已有完整回归。实际浏览器在 1315×816、约 800px、600px 和 200% 缩放下检查长中文名、长路径、键盘和 reduced-motion；批量看一轮、修正后确认一轮。美观、发现入口和切换手感由负责人实际操作确认，DOM 通过不能替代视觉验收。
