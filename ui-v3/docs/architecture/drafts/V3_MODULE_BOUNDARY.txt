# Environment Manager V3 Module Boundary Design

版本：V3.0

状态：模块职责规范


==================================================

# 1. 设计目标


本文定义 V3 各模块职责和依赖关系。


目标：

保证：

- 高内聚
- 低耦合
- 单向依赖
- 可测试


==================================================


# 2. 总体模块结构



EnvironmentManager


    config/


    state/


    matching/


    planning/


    execution/


    history/


    storage/


    ui/


    platform/



==================================================


# 3. 模块依赖方向



允许：


UI

↓

Application Service

↓

Domain Logic

↓

Platform Adapter



Storage作为独立服务提供。



禁止反向依赖。



==================================================


# 4. Config模块



职责：

管理配置定义。



负责：

- TOML读取
- TOML解析
- 配置校验
- 配置保存



输出：

Configuration



==================================================


Config禁止：


不能：

读取Windows环境变量。


不能：

判断匹配。


不能：

生成ChangePlan。


不能：

执行修改。



==================================================


# 5. State模块



职责：

表示系统状态。



负责：

- WindowsSnapshot
- SelectedState
- EditingSession



==================================================


State禁止：


不能：

执行修改。


不能：

决定变化类型。


不能：

保存历史。



==================================================


# 6. Matching模块



职责：

比较：

Actual

与

Desired



输入：


WindowsSnapshot


+

SelectedConfiguration



输出：


MatchResult



==================================================


Matching禁止：


不能：

生成ADD/REMOVE。


不能：

修改系统。


不能：

保存数据。


==================================================


# 7. Planning模块



职责：

生成ChangePlan。



输入：


MatchResult


+

Snapshot


+

DesiredState



输出：


ChangePlan



==================================================


Planning负责：


- ADD判断
- REMOVE判断
- MOVE判断
- REPLACE判断



==================================================


Planning禁止：


不能：

执行计划。


不能：

写Windows。


不能：

操作UI。



==================================================


# 8. Execution模块



职责：

执行ChangePlan。



输入：


Validated ChangePlan



输出：


ExecutionResult



==================================================


Execution负责：


- 执行顺序
- 错误处理
- 执行状态



==================================================


Execution禁止：


不能：

重新计算Diff。


不能：

猜测用户意图。


不能：

修改UI状态。



==================================================


# 9. Platform模块



职责：

提供系统能力。



例如：


Windows Registry Adapter


负责：

读取：

环境变量


写入：

环境变量



==================================================


Platform禁止：


不能：

知道Application。


不能：

知道Profile。


不能：

知道ChangePlan。



==================================================


# 10. History模块



职责：

保存事实。



输入：


ExecutionResult



输出：

HistoryRecord



==================================================


History禁止：


不能：

重新计算变化。


不能：

读取实时Windows。


不能：

修改执行结果。



==================================================


# 11. Storage模块



职责：

持久化。



负责：


- 配置文件
- 历史文件
- 状态缓存



==================================================


Storage禁止：


不能：

包含业务逻辑。


不能：

判断变化。



==================================================


# 12. Application Service模块



职责：

协调流程。



例如：


ApplyService



负责：


选择流程：

1.

读取状态


2.

生成计划


3.

请求确认


4.

执行


5.

保存历史



==================================================


Application Service 是唯一流程协调者。



==================================================


# 13. UI模块



职责：

展示和收集用户操作。



负责：

- 页面
- 控件
- 输入
- 用户确认



==================================================


UI可以：


调用：

Application Service



读取：

ViewModel



==================================================


UI禁止：


不能：

访问Registry。


不能：

解析TOML。


不能：

计算Diff。


不能：

生成ChangePlan。



==================================================


# 14. ViewModel规则



UI不直接使用领域对象。


推荐：


Domain Object


↓

ViewModel


↓

UI



==================================================


ViewModel负责：


- 格式化文字
- 状态展示
- UI需要的数据组合



==================================================


ViewModel禁止：


不能：

改变业务状态。


不能：

创建Operation。



==================================================


# 15. 依赖规则总结



允许：


UI

↓

ApplicationService


ApplicationService

↓

Matching

Planning

Execution


Execution

↓

Platform


History

↓

Storage



==================================================


# 16. 禁止调用关系



禁止：


UI → Registry


UI → DiffEngine


History → Windows


Matching → Executor


Config → Platform



==================================================


# 17. 测试边界



每个模块独立测试。



例如：


Matching测试：

输入Snapshot

输出MatchResult



不启动Windows。



--------------------------------------------------


Planning测试：

输入：

Before

Desired


输出：

ChangePlan



--------------------------------------------------


Execution测试：

模拟Adapter。



==================================================


# 18. 新功能判断规则



新增功能前必须回答：


属于哪个模块？


如果：

一个功能需要修改三个以上核心模块：

需要重新评估设计。


==================================================


# 19. 架构最终目标



V3最终结构：



UI

↓

Application Service

↓

Domain


    Matching


    Planning


    Execution



↓

Platform



↓

Windows



所有模块职责明确。
