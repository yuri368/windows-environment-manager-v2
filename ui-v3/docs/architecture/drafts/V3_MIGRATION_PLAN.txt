# Environment Manager V3 Migration Plan

版本：V3.0

状态：实施指导规范


==================================================

# 1. 迁移目标


V3迁移目标：

在保持已有功能完整性的基础上，将系统从：

“状态判断驱动”

升级为：

“ChangePlan驱动”。


V3不是重新开发项目。


V3应：

- 保留已有数据格式
- 保留已有用户体验
- 保留已有核心规则
- 逐步替换状态计算方式


==================================================


# 2. V2现状分析


V2已经具备：


## 配置管理

包括：

- TOML解析
- Application
- Profile
- Variable


保留。



--------------------------------------------------


## 环境变量规则


包括：

## UI能力


包括：

- 工作台

- 历史


保留。



==================================================


# 3. V2主要架构问题


## 问题1：

多个模块自行判断状态。


例如：

工作台：

自己判断missing。


Windows页面：

自己判断pending。


元素编辑器：

自己判断replace。


导致：

同一个变量出现不同解释。



--------------------------------------------------


## 问题2：

Match承担过多职责。


旧流程：


Match

↓

决定操作



问题：

Match只能回答：

“是否满足”。


不能回答：

“如何达到”。




--------------------------------------------------


## 问题3：

历史记录缺少变化语义。


旧：

用户点击应用。


新：

保存ChangePlan。



==================================================


# 4. 迁移总体原则


## 原则1：渐进式迁移


禁止：

一次性重写。


采用：

模块逐步替换。



--------------------------------------------------


## 原则2：旧逻辑作为验证基准


迁移过程中：

旧规则不能直接删除。


新ChangePlan结果必须通过已有测试验证。



--------------------------------------------------


## 原则3：UI最后迁移


顺序：

数据模型

↓

Diff Engine

↓

执行流程

↓

History

↓

UI



禁止：

先改UI，再补逻辑。



==================================================


# 5. 第一阶段：建立核心模型


目标：

增加：

ChangePlan模型。


新增：


ChangePlan


Operation


ElementMapping



此阶段：

不改变应用行为。


旧流程：

继续运行。


新增：

仅用于测试生成结果。



验收：

同一个输入：

旧逻辑结果

=

新ChangePlan结果



==================================================


# 6. 第二阶段：引入Diff Engine


目标：

统一变化分析。


替换：

旧：

多个模块判断变化。


新：

Diff Engine唯一负责。


输入：


Before

+

Desired



输出：


ChangePlan



==================================================


# 7. 第三阶段：改造Preview


目标：

Preview显示ChangePlan。


例如：


旧：

缺少：

D


新：

计划：


ADD:

D


REMOVE:

C


REPLACE:

C→D



==================================================


# 8. 第四阶段：改造执行模块


目标：

执行只接受ChangePlan。


流程：


用户确认


↓

重新获取Snapshot


↓

验证ChangePlan有效


↓

执行


↓

重新检测



禁止：

执行模块重新计算差异。



==================================================


# 9. 第五阶段：改造History


历史记录保存：


ChangePlan


ExecutionResult



包括：


before

after

operations



禁止：


只保存按钮行为。



==================================================

# 13. 禁止事项


迁移期间禁止：


1.

直接删除V2规则。


2.

3.

4.

引入复杂框架。


5.

一次性重构所有模块。
