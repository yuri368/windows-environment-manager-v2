# Environment Manager V3 Execution Protocol

版本：V3.0

状态：执行流程规范


==================================================

# 1. 目标


本文定义：

ChangePlan生成之后，

如何安全地：

- 预览
- 确认
- 执行
- 验证
- 记录


目标：

保证：

用户看到的变化

=

实际执行的变化


==================================================


# 2. 执行原则


## 原则1：

Preview不是执行。


Preview只展示：

计划。


不会：

- 修改Windows
- 修改配置
- 写History



==================================================


## 原则2：

执行前必须重新验证。


原因：


Preview时：

Windows状态：

A;B;C



用户确认前：

其他程序可能修改：

A;B;D



旧计划已经过期。


因此：

执行前重新读取。



==================================================


## 原则3：

执行只接受ChangePlan。


禁止：

Execute模块重新计算Diff。



错误：

Execute:

读取Windows

自己判断

自己修改



正确：


DiffEngine:

生成ChangePlan


Execute:

执行ChangePlan



==================================================

## 输入：


SelectedConfiguration


+

输出：


PreviewPlan



==================================================

当前值



After:


目标值



Changes:


ADD

REMOVE

REPLACE



==================================================


Preview禁止：


禁止：

点击Preview时写入。


禁止：

修改配置。


禁止：

创建成功History。



==================================================


# 5. 用户确认


用户点击：

应用


之后：

进入执行准备状态。



保存：

planId



但是：

不能直接执行旧Plan。



==================================================


# 6. Revalidation


执行前重新检查。


流程：


重新读取：

WindowsSnapshot



↓

比较：

oldSnapshot

vs

newSnapshot



==================================================


情况1：

未变化。


继续执行。



--------------------------------------------------


情况2：

发生无关变化。


重新生成Plan。



--------------------------------------------------


情况3：

目标变量已经变化。


提示：

环境状态已变化，需要重新确认。



==================================================

before

after

# 9. 写入原则


写入操作：

必须集中。


禁止：


UI:

直接修改


History:

直接修改


Preview:

直接修改



==================================================


正确结构：


UI

↓

ApplicationService

↓

Executor

↓

WindowsAdapter



==================================================


# 10. Windows Adapter


负责：


- Registry读取
- Registry写入
- 环境变量刷新


其他模块不知道Windows细节。



==================================================


# 11. 执行失败处理



如果：

写入失败



ExecutionResult:


success=false


error:


错误信息



==================================================


# 12. 回滚原则



V3不强制自动回滚所有情况。


原因：

Windows环境变量修改可能影响运行中的程序。



==================================================


默认：

记录失败状态。



高级：

根据BeforeSnapshot生成RollbackPlan。



==================================================


# 13. History记录规则

才产生History。



==================================================

Profile


Variable


Before


After


ChangeOperations


Result



==================================================


# 14. No-op处理


如果：


Before

=

After

变化记录。

用户查看行为。
