# Environment Manager V3 Data Model Design

版本：V3.0

状态：数据模型规范


==================================================

# 1. 设计原则


V3 数据模型遵循以下原则：


1. 状态分离

系统中的不同状态必须独立存在。


禁止：

使用一个对象同时表示：

- 配置目标
- Windows当前值
- 用户编辑状态
- 应用结果



--------------------------------------------------


2. 单向数据流


推荐流程：


Configuration

        ↓

SelectedState

        ↓

WindowsSnapshot

        ↓

MatchResult

        ↓

ChangePlan

        ↓

ExecutionResult

        ↓

HistoryRecord



--------------------------------------------------


3. 计算结果不可被UI修改


MatchResult

ChangePlan


均属于计算结果。


UI只能展示。


==================================================


# 2. Configuration


## 作用


保存用户定义的环境方案。


来源：

- TOML
- 配置文件



结构：


Application

    |

    Profile

        |

        Variable



示例：


Application:

Java



Profile:

JDK17



Variable:

PATH



==================================================


# 3. Variable Definition


环境变量定义。


结构：


VariableDefinition {


    name


    scope


    mode


    special


    defaultValue


    choices[]


}



字段说明：



name:

变量名称。


例如：

PATH



--------------------------------------------------


scope:


作用域。


可选：

USER

SYSTEM



--------------------------------------------------


mode:


应用模式。


可选：


replace

append

+append

-append



--------------------------------------------------


special:


是否整体字符串。


true:

不拆分。


false:

按元素处理。



--------------------------------------------------


defaultValue:


默认目标值。



--------------------------------------------------


choices:


可选候选值。



==================================================

表示用户当前选择。


不是Windows状态。


结构：


SelectedState {


    application


    profile


    variables[]


}



例如：


用户选择：


Application:

Python


Profile:

Python3.12



目标：

PATH

=

Python路径



==================================================


# 5. Element


## 作用


表示环境变量中的一个元素。


例如：


PATH:


A;B;C



转换：

[
A,
B,
C
]


Element:


{

    id,

    value,

    index,

    source

}



--------------------------------------------------


id:


稳定身份。


用途：

- 元素编辑
- Diff
- History



--------------------------------------------------


value:


元素实际字符串。



--------------------------------------------------


index:


当前顺序。



--------------------------------------------------


source:


来源：


windows

config

editor



==================================================


# 6. WindowsSnapshot


## 作用


表示某次读取到的Windows状态。


结构：


WindowsSnapshot {


    timestamp


    variables[]

}



VariableSnapshot:


{


    name,


    scope,


    elements[]


}



特点：


只读。


不可修改。


执行前必须重新获取。



==================================================


# 7. MatchResult


## 作用


描述：

目标是否满足当前系统。


结构：


MatchResult {


    variable


    matched[]


    missing[]


    extra[]


    ratio


}



例如：


Windows:


A

B

C



目标:


A

B

C

D



结果：


matched:


A

B

C



missing:


D



ratio:


3/4



==================================================


# 8. ElementMapping


## 作用


描述：

目标元素与当前元素之间的关系。


结构：


ElementMapping {


    targetId


    actualId


    confidence


}



confidence:


可选：


exact

user-confirmed

estimated



说明：



exact:


完全匹配。


例如：

A -> A



--------------------------------------------------


user-confirmed:


用户明确编辑。


例如：

C 改成 D



--------------------------------------------------


estimated:


算法推测。


只能用于展示。


不能直接执行替换。



==================================================


# 9. ChangePlan


## 作用

表示：

结构：

    id


    beforeSnapshot


    desiredState


    operations[]


    createdAt


}

# 18. 编辑状态


用户编辑过程中：

不直接修改：

Configuration


而创建：

EditingSession



结构：


EditingSession {


    original


    current


    dirty


    changes


}



--------------------------------------------------


取消：


current丢弃。



--------------------------------------------------


保存：


current覆盖Configuration。



--------------------------------------------------


应用：

生成ChangePlan。

# 20. 数据隔离规则



禁止：


Configuration

保存Windows状态。



禁止：


WindowsSnapshot

保存用户目标。



禁止：


History

引用实时对象。



禁止：

ChangePlan

引用可变Session。
