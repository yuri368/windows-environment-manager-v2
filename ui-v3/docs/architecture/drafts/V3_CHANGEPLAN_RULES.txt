# Environment Manager V3 ChangePlan Rules

版本：V3.0

状态：核心变化规则规范


==================================================

# 1. 目标


本文件定义：

从当前状态（Actual）

到目标状态（Desired）

之间如何生成：

ChangePlan。



所有：

- UI显示
- Preview
- Execute
- History


必须遵守本规则。



==================================================


# 2. 基本概念



Actual：

当前Windows环境变量值。



Desired：

用户选择方案后的目标值。



ChangePlan：

Actual 到 Desired 的变化描述。



==================================================


# 3. 元素比较原则



普通环境变量：


字符串：

A;B;C



转换：

Element列表：


[
 A,
 B,
 C
]



每个元素拥有：


id

value

index



==================================================


# 4. 元素匹配规则



默认匹配：

trim后比较。

大小写：

保持区分。



例如：


"A"

匹配：

" A "



不匹配：

"a"



==================================================


# 5. MatchResult规则



Match只回答：

是否存在。



例如：


Windows:

A

B

C



目标:

A

B

C

D



结果：


matched:

A

B

C



missing:

D



ratio:

3/4



==================================================


# 6. ChangePlan生成原则



Diff Engine必须回答：


“为了达到目标，需要执行什么变化？”



而不是：

“字符串哪里不同？”



==================================================


# 7. ADD规则


ADD表示：

目标需要某元素，

但是当前不存在。



例如：


Actual:

A

B



Desired:

A

B

C



生成：


ADD C



==================================================


# 8. REMOVE规则


REMOVE表示：

当前存在，

但目标不需要。



例如：


Actual:

A

B

C



Desired:

A

B



生成：

REMOVE C



==================================================


# 9. REPLACE规则



REPLACE表示：

明确知道：

旧元素对应新元素。



例如：


Actual:

A

B

C



用户编辑：


C → D



生成：


REPLACE


C

↓

D



==================================================


# 10. 未知变化处理



如果：

无法确认元素关系。


例如：


旧：

A

B

C



新：

D

E

F



禁止：


A→D

B→E

C→F



因为：

没有可靠依据。



正确：


REMOVE:

A

B

C


ADD:

D

E

F



==================================================


# 11. 用户输入字符串修改规则



用户直接修改：

PATH输入框。



例如：

旧：


A

B

C



修改：


A

B

D



默认：

不产生REPLACE。



生成：


REMOVE C


ADD D



原因：

用户只是修改字符串。


没有元素身份。



==================================================


# 12. 元素编辑器规则



元素编辑器拥有稳定ID。


因此可以产生：

REPLACE。



例如：


元素：

id=3


value:

C



修改：


value:

D



生成：


REPLACE


id=3

C→D



==================================================


# 13. append模式规则



append目标：

只保证目标元素存在。



例如：


Actual:

A

B



Desired:

A

B

C



生成：

ADD C



--------------------------------------------------


如果：

Actual:

A

B

C



Desired:

A

B

C



生成：

无变化。



--------------------------------------------------


不执行：

删除。

排序。

去重。



==================================================


# 14. append已有元素修改



例如：


Actual:

A

B

C



用户目标：

A

B

D



append模式：


C不存在于目标？

根据append语义：

不会自动删除C。


结果：

ADD D



同时：

保留C。



==================================================


# 15. replace模式规则



replace：

目标完全覆盖。



例如：


Actual:

A

B

C



Desired:

A

B

D



生成：


REMOVE:

C


ADD:

D



==================================================


# 16. special规则



special=true



整个字符串作为一个元素。



例如：


A;B;C



不是：

A

B

C



而是：

"A;B;C"



==================================================


special变化：


旧：

A;B;C



新：

D;E;F



生成：


REPLACE


整体值变化。



==================================================


# 17. 空元素规则



空元素属于有效元素。



例如：


A;;



拆分：

A

(empty)

(empty)



禁止：

filter(Boolean)



==================================================


# 18. 重复元素规则



重复元素保留。


例如：


A;A;B



元素：


A(id1)

A(id2)

B



禁止：

自动去重。



==================================================


# 19. MOVE规则



MOVE只表示：

元素身份存在，

但是位置变化。



例如：


Actual:

A

B

C



Desired:

B

A

C



生成：


MOVE:

A

B



==================================================


# 20. REMOVE + ADD 与 REPLACE区别



区别：


REMOVE + ADD：

不知道身份关系。



REPLACE：

知道旧元素对应新元素。



来源：


- 用户确认
- 稳定ID编辑



==================================================


# 21. “待修改”显示规则



待修改不是底层操作。



底层：

ADD

REMOVE

REPLACE

MOVE



UI可以组合显示。



例如：


REPLACE:

C→D



显示：

待修改



==================================================


# 22. “待追加”显示规则



待追加：

对应：

ADD



例如：


ADD:

D



显示：

D

待追加



==================================================


# 23. Preview规则



Preview必须展示：


Before:

旧值


After:

目标值


Operations:

变化列表



禁止：

Preview重新猜测。



==================================================


# 24. 重新检测规则



用户点击应用后：


不能直接相信旧ChangePlan。



流程：


重新读取Actual


↓

重新生成Diff


↓

确认有效


↓

执行



==================================================


# 25. 总结原则



V3变化判断遵循：


能确认身份：

REPLACE


不能确认：

REMOVE + ADD


只缺少目标：

ADD


目标不需要：

REMOVE


顺序变化：

MOVE



永远：

不猜用户意图。
