# Environment Manager V3 Architecture Design

版本：V3.0

状态：架构设计规范

用途：
本文件用于指导 Environment Manager V3 的长期架构设计。
所有后续代码修改、模块拆分、UI实现、真实环境接入，都应遵循本文定义。

==================================================

# 1. 核心设计目标

V3 的目标不是简单修改 Windows 环境变量。

V3 应作为一个轻量级配置状态管理系统，负责管理：

1. 用户期望状态（Desired State）
2. 当前系统状态（Actual State）
3. 两者之间的变化计划（Change Plan）


核心原则：

所有 UI 展示、应用执行、历史记录，都必须基于统一的 ChangePlan。

禁止：

- UI 自己判断待追加
- Windows 页面自己计算差异
- 历史记录重新推断变化
- 多个模块分别实现 Diff


==================================================

# 3. 核心对象定义


## 3.1 Configuration

配置定义。

来源：

- TOML
- 配置文件


特点：

- 静态数据
- 用户编辑对象
- 不代表当前系统状态


示例：

Java

    JDK17

        JAVA_HOME

        PATH


注意：

Configuration 不代表 Windows 当前值。


==================================================


## 3.2 Selected Configuration

当前用户选择的目标方案。


表示：

用户希望系统达到的状态。


例如：

应用：

Java


方案：

JDK17


变量：

PATH


目标：

%JAVA_HOME%\bin


注意：

Selected Configuration ≠ Windows 当前状态。


==================================================


## 3.3 Windows Snapshot

Windows 当前环境快照。


来源：

未来：

- Windows Registry


当前：

- Demo Snapshot


示例：


PATH:

A

B

C


特点：

- 只读
- 表示真实状态
- 不包含用户意图


==================================================


## 3.4 Element

环境变量元素。


普通变量：

A;B;C


转换：

[
    A,
    B,
    C
]


Element:

{
    id,
    value,
    index
}


Element ID 用于：

- 元素编辑
- Diff分析
- 历史记录


==================================================


# 4. Match Engine


职责：

回答：

“当前 Windows 是否满足目标配置？”


输入：

Windows Snapshot

+

Selected Configuration


输出：

MatchResult


例如：

目标：

A

B

C

D


当前：

A

B

C


结果：

matched:

A

B

C


missing:

D


ratio:

3/4


==================================================


Match Engine 不负责：

- 添加
- 删除
- 替换
- 应用


Match 只描述当前状态。


==================================================


# 5. Diff Engine


职责：

回答：

“从当前状态达到目标状态，需要发生什么变化？”


输入：

Before

+

Desired


输出：

ChangePlan


==================================================


# 6. ChangePlan


ChangePlan 是 V3 核心对象。


所有模块必须消费 ChangePlan。


结构：

ChangePlan:

    before

    desired

    operations


operations:

    ADD

    REMOVE

    MOVE

    REPLACE


==================================================


# 7. Change Operation


## ADD

新增元素。


例如：

Before:

A

B


After:

A

B

C


结果：

ADD C



--------------------------------------------------


## REMOVE

删除元素。


例如：

Before:

A

B

C


After:

A

B


结果：

REMOVE C



--------------------------------------------------


## MOVE

移动顺序。


例如：

Before:

A

B

C


After:

B

A

C


结果：

MOVE A

MOVE B



--------------------------------------------------


## REPLACE


替换是高级解释。


底层仍然：

REMOVE old

+

ADD new


只有以下情况允许：

1. 用户通过元素编辑器明确修改

2. 稳定身份关系明确


禁止：

仅根据字符串变化强行判断替换。


==================================================


# 8. Match 与 ChangePlan 的区别


Match：

回答：

当前是否满足？


例如：

3/4匹配



ChangePlan：

回答：

如何达到目标？


例如：

ADD:

D


REMOVE:

C


REPLACE:

C -> D



两者不能混淆。


==================================================


# 9. UI设计原则


所有页面：

只能读取：

- MatchResult
- ChangePlan
- Windows Snapshot


禁止页面自行计算：


错误：

Windows页面：

发现不存在

↓

显示待追加


错误：

元素编辑器：

自己重新判断替换



正确：

所有页面：

读取统一 ChangePlan。


==================================================

## 工作台


负责展示：

- 当前方案
- 匹配情况
- ChangePlan摘要


例如：

PATH


匹配：

3/4


变化：

新增：

D



--------------------------------------------------


## Windows环境页面


负责展示：

Windows Snapshot

+

ChangePlan


不负责修改规则。


--------------------------------------------------


## 元素编辑器


负责：

创建明确元素身份变化。


例如：

C

生成：

C -> D



--------------------------------------------------


## History


保存：

ChangePlan执行结果。


禁止只记录：

“用户点击应用”。


必须保存：

before

after

operations

# 12. Mode规则


## replace


完全替换。


底层：

REMOVE旧元素

ADD新元素



--------------------------------------------------


## append


追加缺失元素。


规则：

- 已存在元素保持
- 不自动删除
- 不自动去重
- 保留顺序



--------------------------------------------------


## special


整体字符串。


规则：

- 不拆分
- 不分析内部元素


==================================================


# 13. 禁止事项


禁止：

1.

多个模块分别计算Diff


2.

UI根据字符串猜用户意图


3.

把所有不存在元素都认为新增


4.

把所有变化都认为替换


5.

为了显示效果修改真实数据语义



==================================================

# 15. 最终目标


V3最终应成为：

轻量级配置状态管理系统。


核心能力：

可靠管理：

Desired State

与

Actual State

之间的变化。


而不是简单修改环境变量。
