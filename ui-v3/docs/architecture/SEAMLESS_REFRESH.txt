V3 seamless refresh supplement — 2026-10-16

Owner requirement: seamless and accurate refresh, discussed with Astra and the ChatGPT architecture adviser. This supplement supersedes V3.2 section 4 snapshot-equality requirement and section 10 manual rebase; supersedes conflicting V3.3 stale-display requirements. V3 demo only; no Registry, V2 migration or new framework.

1. OriginalSelected and initial matched baseline remain immutable for the editing session. CurrentSelected follows user input. Actual is always the latest target-specific exists/raw/type/revision snapshot. Never capture a replacement baseline merely because Actual changed.

2. removalState is immutable, session-only evidence for original uniquely matched occurrences, folded forward after each verified target commit. It is neither a TOML field, persistent identity nor proof of application ownership. Unknown transitions, revision-only ABA, changed original text or removed original occurrences revoke automatic deletion eligibility permanently for that editing session. A later equal string cannot restore it. Initially repeated/missing values do not gain eligibility on refresh. Current duplicate matches and current shared dependencies remain protected. Trusted direct-edit audit must match the complete previous snapshot, cover old/new indices and raw slices, and describe the committed result. Unchanged original occurrences can retain eligibility at their new positions. Values/empty slices/order remain verbatim. Context target/mode/special mismatches still block incompatible plans.

3. DemoPlan alone computes current operations and After. Snapshot change is not a whole-plan invalidation. Safe additions continue; unresolved deletion is a non-executable duplicate/shared/continuity issue using current indices, never a fictional removal. Workbench and preview use that frozen plan's real After. A partially applied request retains its original baseline, input and pending deletion intent; history records only actual operations and explicitly describes partial completion. A fully resolved applied request ends its edit session.

4. Known writes update removalState for all sessions with the same canonical target, including inactive profiles. Unknown snapshot updates synchronize to a revoked state without re-capturing original intent. No target-wide journal or polling loop is needed. Existing target writes, refresh detection and window refocus drive current projections. This is simulated browser memory; it is not real Windows monitoring.

5. Preview remains open on relevant changes, preserves reasonable scroll/focus and raw disclosures, replaces the frozen rows and advances its version. Its previous confirmation is invalid. Updated previews require a distinct review step before final confirmation; the review action never writes. Confirm revalidates every target, current selection/context, removalState and protected dependencies. A change discovered by that click refreshes and returns without applying either old or new rows. Unrelated targets do not invalidate the preview. All targets validate before the synchronous memory commit, with no await between validation and writes. The write boundary independently refuses stale frozen plans. History consumes precisely the frozen applied plans.

6. Arbitrary open element-editor drafts are not silently merged into an unknown new snapshot. Before closing, validate and commit the editor's frozen plan. On stale rejection keep all session rows/IDs/display order/deleted drafts and serialized draft visible; show latest Actual separately. Never dismiss before rejection, overwrite new values with old afterRaw, or claim arbitrary three-way merge support.

7. Existing source/context changes still end old sessions. Restore/cancel/reset keep their prior semantics except that cancellation of preview never discards the edit intent. Windows inventory remains snapshot-only; scheme analysis belongs to workbench/preview.

Implementation acceptance evidence is separate from this contract. Tests must cover known audit propagation, duplicate/missing-origin protection, unknown/ABA and changed/removed identity non-revival, current shared protection, partial completion retention, batch stale atomic rejection, repeated preview refresh, final plan/history consistency, draft/selection preservation and empty/raw-string boundaries.
