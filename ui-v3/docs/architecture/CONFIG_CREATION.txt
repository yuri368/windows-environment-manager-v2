负责人指出 TOML 编辑器只能修改已有内容。本轮补齐应用、方案、变量的创建入口，候选值沿用现有添加与编辑。仅浏览器配置草稿，不连接真实文件或系统环境。

1. 应用、方案、变量使用紧凑行内表单。新应用一次创建首个方案与首条变量，首方案为默认方案；新方案一次创建首条变量，不改变已有默认方案。创建成功后定位新记录的默认值字段；默认值初始为空字符串，继续支持候选值和其他既有属性。
2. 创建先构造候选配置并通过完整 ConfigFormat.errors 校验，才一次提交。失败不留下节点、不改变导航或勾选。名称原文保留，应用/方案精确去重；方案不能使用 default_option；变量按 V2 的逐字符大小写规则及作用域判重，双作用域按既有数组导出。同目标既有 Special 属性沿用，整体目标使用 replace，表单说明并禁用不兼容模式。
3. reset 捕获原对象的配置字段到 WeakMap。配置差异与还原按对象身份关联原始配置，不依赖 initialApps 下标。新增应用/方案/变量显示为结构新增；新增父节点包含其子树，不重复记成原属性修改。临时编辑状态与基线均不进入 TOML。
4. 还原配置移除新增节点，修正应用、方案、变量、profileChoice 与批量勾选；原有对象、运行草稿和未受上下文改变影响的删除依据保留。恢复作用域/模式/Special 等属性时继续遵循既有上下文失效规则。模拟 Windows 与历史不因配置新增或还原而修改。
5. 新增不等于应用，新增应用的 active 初始为空。新增目标参与工作台与原预览路径；共享依赖变化仍触发原版本重审流程，不扩大删除资格、不更改 DemoPlan 或元素审计。导出继续使用 V2 格式。

2026-10-18 负责人交互反馈补充：分层命名

新增应用第一步只填写应用名称；新增方案第一步只填写方案名称，不要求同时填写首个变量、作用域或模式。已命名但缺少下级内容的容器在现有 ConfigEditor session 草稿内展示，左导航标记“草稿”，可离开后恢复；取消首个变量填写返回已命名的空方案草稿，放弃、还原配置和重置清除对应草稿。
