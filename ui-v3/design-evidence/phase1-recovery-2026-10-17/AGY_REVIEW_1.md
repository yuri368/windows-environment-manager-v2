### 一、 剩余具体风险与建议（按优先级排序，共 5 条）

#### 1. 【高优先级·视口预算】选定值增长对三值对照下半部的垂直挤压风险
* **具体风险**：在目标渲染尺寸（1383×851）下，当前值与结果标题基准 y 约 615px。当用户输入 `%HADOOP_HOME%\bin;;%HADOOP_HOME%\bin; H:\开发工具\长目录 ;` 这类多段并带提示的内容时，选定值容器若完全无限制向下撑开，下方的“Windows当前值”与“plan.after”双列及其首行内容将被推入 851px 视口折叠线下，破坏“无需整页滚动即可对照首行”的承诺。
* **修改建议**：工作台单变量输入区允许内容自适应增长，但须设置合理的 `max-height` 弹性阈值（如约 100px~120px，约 3~4 行高度）配合局部纵向滚动，锁死对照区域头部 y 坐标上限，确保双列标题与首行在 851px 高度内恒定露头。

#### 2. 【高优先级·反馈来源】草稿诊断与系统既有脏状态的视觉混淆风险
* **具体风险**：工作台输入框正在输入带重复/空元素的内容，Windows 表中的 System PATH 也恰好模拟了 2 个空元素与重复的 `System32`。若两处的重复/空元素提示样式完全同级同构，用户极易把“当前选定值草稿的待整理警告”误读为“Windows 真实环境现有错误”，或误以为预览计算尚未生效。
* **修改建议**：从视觉归属上拉开清晰来源差异：
  * **选定值内提示**：定性为“输入草稿待整理（Draft / Pending Clean）”，仅在输入框内附着轻量临时标记；
  * **Windows 表内提示**：定性为“注册表实际状态（Live Registry State）”，使用既有明确铭牌与状态标签；
  * **plan.after 预览**：保持无告警的最终干净状态，体现“按既有规则自动归一化”。

#### 3. 【中优先级·窄屏可达性】600px 极端换行时的无空白长路径溢出与按钮挤压风险
* **具体风险**：600px 窄屏虽然开启了自然换行，但在 Windows 表或长变量名中，像 `H:\开发工具\长目录...` 这类长连续无空格路径，若未严格声明断字规则，会导致文本溢出容器形成横向微滚动条，进而将右侧常驻 28px 的“编辑”和“原文”操作挤出可视范围或产生遮挡。
* **修改建议**：
  * 模拟当前值及长文本单元格强制补充 `overflow-wrap: anywhere; word-break: break-all;`；
  * 28px 常驻操作单元必须声明 `flex-shrink: 0; white-space: nowrap;`，在字段折行时独立沉底或右对齐吸附，确保任何极限折叠下操作入口绝对可点。

#### 4. 【中低优先级·交互联动】Enter 键从 Windows 表跳转定位工作台时的状态保护
* **具体风险**：Windows 表支持按 Enter 定位到工作台对应变量编辑。若此时工作台已有正在编辑的“自定义值草稿”，跨组件焦点跳转容易引发页面视口大幅跃迁，或误触发重新初始化。
* **修改建议**：Enter 定位只执行两项安全动作：
  1. 调用 `scrollIntoView({ block: 'nearest', behavior: 'smooth' })` 定位至变量行；
  2. 聚焦至对应输入框并呈现高亮轮廓，**绝对不重置、不覆盖**当前输入框内的草稿文本与来源状态。

#### 5. 【低优先级·认知一致性】Special 变量的分号不可拆分呈现
* **具体风险**：System PATH 的分号是列表分隔符，支持 token 粒度的铭牌、跳转和独立重复分析；但 Special 命令变量含分号且为整体不可拆分字符串。若在 Windows 当前值中渲染形态与 PATH 过于相似，键盘导航（Tab/方向键）在分号处无法移动时会给用户造成“按键失效”或“没有检测到空项”的困惑。
* **修改建议**：Special 变量在 Windows 表中始终呈现为单一不可分割的整块原子铭牌，并附带小尺寸单值标识（如 `[Special]` 或单底色外框），关闭内部 token 游标跳转，与普通追加型列表拉开交互预期。

### 二、 最小验收动作（建议 4 步）

1. **视口截断实测（1383×851 窗口）**：
   * 在工作台 Path 输入 `%HADOOP_HOME%\bin;;%HADOOP_HOME%\bin; H:\开发工具\长目录 ;`；
   * 肉眼与尺规验证：下方“Windows当前值”与“plan.after”双列标题栏 y 坐标稳定在视口内，首行对比数据及“查看方案预览”按钮无需整页滚动即可完整可见。
2. **600px 窄屏折行与按钮可达性验证**：
   * 将浏览器视口宽度拖至 600px，查看包含重复 `System32` 和多空元素的 System PATH；
   * 验证：内容自然垂直换行，无水平横向滚动条，右侧 28px “编辑”与“原文”文字按钮未被截断、未被推入可视区外，仍可直接点击。
3. **键盘流与跨组件定位闭环**：
   * 鼠标离开页面，纯键盘按 Tab 进入 Windows 表，用方向键/Home/End 在 PATH 的各个 token 铭牌间切换；
   * 在某一项上按 `Enter` 键，确认焦点瞬间平滑转移至工作台对应变量的输入框中，且输入框现有未保存草稿未受任何破坏。
4. **Special 命令变量渲染校验**：
   * 查看包含分号的 Special 命令变量行，验证其作为一个整块呈现，不显示“发现重复/空元素”虚假标记，展开原文按钮能正确展开完整 raw 字符串。

### 三、 无需修改的部分

1. **核心业务与计算规则**：普通变量按 `;` 拆分/trim/去重、Special 变量原子性、追加（`+append`/`-append`/`append`）与替换计算逻辑、写入自动整理逻辑。
2. **底层状态契约**：DemoPlan 结构、Audit 追溯、确认版本机制（version-bound confirmation）、删除资格（deletion eligibility）状态计算。
3. **范围外模块布局**：配置编辑器内部布局、批量切换管线、历史记录总面板。
4. **已确认修复项**：`shell .inspecthead strong::before` 仅直接命中标题（已排除审阅菱形误伤）；恢复的可展开原文机制（不带默认大说明块）；保留的三种区分样式（主悬停起点 / 同 occurrence ID / 仅同值重复）。
5. **既有自动化验证**：8 个已通过的 JSDOM 专项测试代码与断言契约保持原样。
