原则上批准修复方案，但第 2 项需要补充一条约束：原始换行保真必须同时覆盖普通元素和 special=true 的整体字符串。

我已经对照 Claude 基线中的 removeLiveRow()、restoreGhost()、textarea 输入处理和 CSS 加载顺序。整体方案足够轻量，不需要回退 Claude 的视觉设计，也不需要修改 DemoPlan。

Claude UI 审查问题最小修复契约

状态：批准实施
基线：5b05e998

1. 删除前草稿恢复

同意增加会话级：

deletedDrafts: Map<ElementId, {id, value}>

规则：

删除原始 live row 前，保存删除瞬间的当前内容。

再次删除同一原始 ID 时覆盖旧草稿。

删除本次新增的 ID，不创建删除草稿或 ghost。

普通 ghost“取消删除”优先恢复 deletedDrafts 中的内容。

保持原始稳定 ID 和 ghost 当前 displayOrder 位置。

恢复成功后清理该 ID 的缓存和删除采纳来源。

“建议删除”绿色 ✓ 撤销仍恢复 OriginalRaw，不恢复手动编辑草稿。

Restore 清空 deletedDrafts；Cancel 销毁整个会话。

Apply、Audit、History 不保存 deletedDrafts。

注意：ghost 可继续显示原始 Windows 元素，以保持删除痕迹语义；其“取消删除”按钮提示应说明会恢复删除前的编辑内容。

2. textarea 原始字符保真

同意移除普通元素 textarea 的 Enter 拦截和全局 CR/LF 删除。

允许显式输入换行；自动视觉折行不进入真实 raw。

同意使用最小差异映射：

将旧 raw 的 CRLF、CR 归一化为 LF，得到比较视图。

与新的 textarea.value 比较。

当归一化结果完全相等时，保留原始 raw。

否则计算不重叠的最长公共前缀和后缀。

将两端位置映射回旧 raw 的原始 UTF-16 索引。

保留未修改区间的原始 CRLF / CR / LF。

仅使用 textarea.value 中的内容替换实际编辑区。

新输入的换行使用 LF，不尝试猜测用户期望 CRLF 还是 CR。

补充要求：该保真处理也必须适用于 special=true 的整体字符串 textarea。

原因：Special 也是 textarea，其 .value 同样存在浏览器换行归一化行为。只修普通元素会留下同类数据丢失缺陷。

保留原有分号、NUL 验证规则，不将普通元素的分号限制施加到 Special 上。

3. 删除草稿与字符保真的组合测试

必须验证：

修改 B→B1，删除 B1，再取消删除，仍为 B1。

修改后删除，移动 ghost，再恢复，ID、内容和位置均正确。

恢复后再次编辑、再次删除，保存最新草稿。

重复元素仅恢复明确 ID。

原始空元素与显式空字符串不混淆。

建议删除的撤销仍恢复原始值。

Restore、Cancel、Apply/History 不包含缓存状态。

LF、CRLF、CR 及混合换行保真。

在换行前后插入、删除字符，不意外修改其他换行。

普通元素及 Special 均通过原始字符串测试。

仅视觉自动折行不会改变 raw。

4. 600px 布局冲突

同意在后加载的 shell-ui.css 中增加 max-width:620px 规则，恢复 .applist 的两列 Grid。

要求：

继续使用原有 150px 最大高度及滚动。

子项不得出现横向溢出。

在真实 CSS viewport 为 600px 的情况下测试，而不只设置外层窗口物理尺寸。

不扩大为全页面响应式重构。

5. 测试维护

更新两处过时断言：

source is-custom 使用 classList 或包含关系检查。

采纳建议后焦点应留在重新创建的建议按钮。

不得仅为了通过旧测试而回退新 UI。

必须重新执行全部现有脚本，并针对本轮数据保真和交互增加回归测试。

6. 实施边界

允许：

最小会话缓存。

textarea 纯字符串映射 helper。

局部 CSS 修复。

对应测试及证据更新。

禁止：

修改 DemoPlan 核心业务。

重建编辑状态系统。

回退 Claude 的视觉和动画方向。

接入真实 Windows 注册表。

修改 V2、合并 main 或发布 Release。

最终原则：撤销删除恢复用户当时的草稿；编辑字符串保留未触碰的原始字符；视觉变化不能意外修改业务数据。

两个特别容易漏掉的地方

第一，删除草稿缓存必须在移除 live row 之前写入。 否则保存到的可能已经是原始快照，问题只是换了个地方存在。

第二，字符映射不能直接拿归一化后的索引切割原始字符串。 一个 CRLF 在比较视图中占 1 个字符，在原始字符串中占 2 个 UTF-16 码元，必须显式建立边界映射。同时要避免公共前后缀重叠。

最终裁定：批准 Codex 开始实施。 修复完成后提交源码、完整回归报告及实际浏览器测试结果。本轮只针对已经确认的问题验收，不再扩展新的 UI 功能。
