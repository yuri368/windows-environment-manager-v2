写作
V3.5 删除痕迹与元素展示一致性契约

状态：批准实施
基线：V3.4
范围：仅三项 UI 展示与交互修正

一、元素 Token 不允许标签或勾选独立换行

适用于元素编辑器的 token：

整个 token 使用 inline-flex。

元素值允许在方框内部换行。

新增、删除、替换、移动标签保持为不可收缩子项。

匹配勾选 ✓ 保持为不可收缩子项。

标签、勾选不能脱离所属 token。

长路径不得造成水平溢出。

保留现有紧凑尺寸及色彩。

允许整个 token 自动换到下一行，不允许同一 token 的标签或勾选被单独挤到框外。

优先使用现有 CSS 修复，避免修改通用组件的数据结构。

二、工作台 Actual 与 After 的删除状态
Windows 当前值（Actual）

这里的元素仍然真实存在于当前演示快照。

确定计划删除时：

保留原始位置。

保留“待删除”标签。

使用现有删除色系。

可以继续显示删除线。

应用后的值（After）

这里是结果预览，不代表 Windows 已执行。

对于计划删除的元素：

保留幽灵 token。

使用静态斜线纹理。

使用虚线边框。

保留删除线。

标签建议使用“结果排除”。

区域辅助说明：

“应用后预览。划线元素不计入最终写入值，当前尚未应用。”

不再把 Actual 与 After 的删除 token 做成完全相同的状态。

真实最终写入值继续直接读取冻结的 plan.after。

幽灵元素不得参与序列化、匹配计算、历史或操作生成。

三、编辑器删除幽灵行
数据来源

只从以下两组数据生成：

originalRows

session.rows（live rows）

满足：

原始稳定 ID 存在于 originalRows，但已不在 session.rows 中。

即生成一条展示专用幽灵行。

不增加额外的 deletedRows 状态集合。

幽灵行外观

使用原始序号。

保留原始字符串。

使用静态斜线纹理和虚线边框。

显示“本次编辑已移除”。

辅助说明“不计入结果”。

不显示可编辑输入框。

不提供删除、移动或拖动控件。

幽灵行绝不能进入 live rows、elementTotal、serialized、ChangePlan 或 History。

幽灵行位置

采用你提出的锚点规则：

从 originalRows 按原始顺序取出已删除元素。

找到该元素后面第一个仍存活的原始稳定 ID。

如果存在，将幽灵插在该存活元素之前。

如果不存在，将幽灵放在列表末尾。

多个幽灵使用原始顺序稳定排列。

不修改任何 live row 的实际顺序。

例如：

原始：A、B、C、D

当前 live：A、D

展示：A、B（已移除）、C（已移除）、D

真正序列化：A;D

如果用户重新排序 live rows，幽灵行仍按上述锚点定位，但不能反过来改变 live rows 的顺序。

特殊情况

删除重复值时，仅对应稳定 ID 变成幽灵。

手动删除原元素也生成幽灵。

本次新增又删除的元素不产生幽灵。

删除全部 live rows 后，幽灵仍可展示，但真实结果继续是变量不存在。

还原本次编辑后，幽灵全部消失。

取消弹窗时，不写入演示 Windows 快照。

联动高亮

幽灵行可以保留原始 data-element-id，复用已有的鼠标关联高亮。

但幽灵行不能被事件逻辑识别为可编辑 live row。

不需要为幽灵新增常规键盘 Tab 焦点，也不新增独立的选择状态。

四、编辑器对照及摘要

元素编辑器中：

“打开时的值”仍保留完整原值。

“编辑后的值”仍保留实际删除 ghost。

编辑列表也可出现同一稳定 ID 的只读幽灵。

三处联动只基于原始稳定 ID。

底部摘要仍由 session.plan.operations 决定。

方案建议保持 V3.4 的独立语义，不因为幽灵行出现就自动视为采纳。

建议只在编辑器列表幽灵上显示“本次编辑已移除”；编辑后的值继续使用实际删除的语义标签。

五、本轮验收要求

长元素包含文字、✓、标签时，不出现单独折行或横向溢出。

Actual 显示待删除，After 幽灵显示结果排除。

After 幽灵不污染最终写入字符串。

手动删除和采纳建议删除均出现编辑器幽灵行。

重复元素仅对应稳定 ID 产生幽灵。

重排 live rows 后，幽灵位置符合锚点规则，序列化顺序不变。

新增再删除不残留幽灵。

全部 live rows 删除后，变量不存在的规则不变。

还原和取消清除本次编辑痕迹。

Preview、Apply、History 的底层结果和 V3.4 完全一致。

六、严格禁止扩大范围

本轮不修改：

DemoPlan 核心计算。

V3.2 增删规则。

V3.3 三值对照的数据契约。

V3.4 建议与实际编辑隔离规则。

temp.html 的执行、快照验证及历史逻辑。

不引入新框架，不连接 Windows 注册表，不修改 V2，不合并 main，不发布 Release。

最终目标：

删除操作既能被用户清楚地看见，又不会改变真实编辑列表及执行语义。

Codex 可以开始实施。本轮主要检查幽灵行是否纯粹属于展示层，以及长路径换行有没有破坏紧凑布局。无需另起架构设计，也不用借机重新装修整个编辑器。
