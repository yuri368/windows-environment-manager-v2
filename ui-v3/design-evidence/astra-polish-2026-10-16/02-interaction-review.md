# 第 2 轮交互边界审查

审查基线：`56dbf6030aa11a33f192d91761e7063803d9c350`；分支：`v3/astra-interaction-polish-20261016`。本报告只审查代码与契约，没有修改产品代码、运行测试或等待截图。已阅读根及 `ui-v3/AGENTS.md`、架构索引、`SEAMLESS_REFRESH.txt`，并核对 `temp.html` 与 `demo-plan.js`、`windows-elements.js` 的对应实现。

建议按既定范围推进。最高风险不是配色，而是把“删除保留”“无写入”“预览待审阅”“上下文无效”合并成一个不可执行状态。摘要、按钮、计数与下一步必须分别表达这四种语义。

## 1. 决策摘要：先区分执行门槛，再表达结果

展示层只消费当前冻结的 `action.rows` / `row.plan`。不要为了生成摘要重新调用单变量计划、重建 After、推断删除或创建新的业务状态。以下布尔量是只读视图投影：

- `blocked`：任一 `plan.valid === false`，或本次应用的任一参与成员 `mode === 'append'`。
- `needsReview`：`action.reviewedVersion !== action.version`。
- `retained`：任一 plan 存在 `duplicate`、`shared`、`continuity` issue。
- `hasOperations`：任一冻结 plan 的 `operations.length > 0`。不要用 dirty、检测匹配比例、ghost 数量或字符串展示是否相等替代它。

| 条件（按顺序） | 主摘要 | 辅助说明与确认按钮 |
| --- | --- | --- |
| 撤销预览 | 撤销范围说明 | 明示“原型未实现撤销执行”。确认禁用，文案“撤销暂不可执行”。不得显示“可应用”或将说明文字伪装为 After。 |
| blocked | 整批暂不可应用 | 列出全部阻塞目标及各自原因。确认禁用，文案“暂不可模拟应用”。保留查看目标、原文、关闭能力。 |
| 非阻塞且 needsReview | 预览已更新 · 待重新审阅 | 主按钮“已查看更新，继续确认”。这次点击仅记录当前版本已审阅，不写入、不提交偏好、不关闭。随后按钮转为对应的确认文案。 |
| 非阻塞、已审阅、retained 且 hasOperations | 可应用安全变更 · 含保留项 | “未解决删除将保留，其他计划操作可模拟应用”。按钮“模拟应用安全变更”。不能暗示整批所有输入都将完成。 |
| 非阻塞、已审阅、retained 且无 operations | 暂无可执行变更 · 删除仍保留 | 保留现有确认能力，不借 UI 改算法。按钮可用“模拟确认当前计划”；说明“未解决删除和当前输入仍保留；已解决记录仍可提交成功选择”。不能宣称“全部完成”，也不能说“已有安全操作应用成功”。 |
| 非阻塞、已审阅、无 retained 且 hasOperations | 可模拟应用 | 按钮“模拟确认应用”。 |
| 非阻塞、已审阅、无 retained 且无 operations | 当前值无需变更 | 按钮“模拟确认选择”。说明“确认仍可记录本次成功选择”；不能禁用按钮或自动关闭。 |

阻塞与审阅是两个独立维度：若两者同时存在，主摘要优先表达阻塞，仍展示“预览已更新”副提示。不要因进入阻塞视图而改写 `reviewedVersion`；下一次可执行计划仍须按版本审阅。

目标卡片可以显示局部“有变更”“无值变更”“含保留项”，但整批被阻塞时必须附带“本批次暂不执行”，避免安全目标的绿色“可应用”误导用户。单目标局部状态不得覆盖总确认门槛。

计数分开：`targets.length` 是变量记录数，`rows.length` 是合并目标数；变更目标数来自带 operations 的 row。issue 数仅称“删除保留提示 N 条”，同一个元素可能因多个 request 重复出现，不能直接称“保留 N 个唯一元素”。原有三值 tally 的“保留”包含普通保留元素，不等于未解决删除数。

## 2. 原因解释与下一步：不承诺当前原型没有的解决能力

| 原因 | 准确解释 | 可用下一步与禁止暗示 |
| --- | --- | --- |
| duplicate | 原匹配或当前匹配存在重复，无法安全确定自动删除对象；本次保留。 | “查看当前元素”。只读 issue 未标明重复发生在哪个阶段时，不声称“当前一定存在多个副本”。即使现在只剩一个，原先重复也可能仍受保护。不能承诺刷新或删除另一个副本后自动恢复资格。 |
| shared | 当前还有其他选定输入需要此元素，本次保留。 | “查看当前元素”或返回检查相关方案；只有现有数据提供保护方时才列出具体名称。不要从 issue.value 猜应用归属，也不要提供“强制解决共享”按钮。 |
| continuity | 原匹配元素的连续性无法确认，本次不自动删除。 | “查看最新当前值”。说明“相同文本再次出现也不会自动恢复删除资格”。不要文案“重新刷新即可解决”“重新建立基线”或自动丢弃原编辑。 |
| stale | 编辑目标、模式或特殊值上下文与原编辑不兼容。 | 整批阻塞；根据 issue.fields 展示作用域/目标、模式、特殊值类型等实际字段。提示返回核对输入与上下文，保留输入。此处不是普通 Actual 更新，不应写“当前值变动，需要手动刷新”。 |
| conflict | 同一目标的多个请求无法合并。 | 整批阻塞；显示参与应用/方案与模式，引导调整本次选择。不能任选一个请求、跳过冲突目标或只应用其他目标。 |
| append 未支持 | 本批次包含自定义排序，但原型尚未实现排序确认。 | 即使 operations 为空或有其他安全目标，也整批阻塞。文案“返回调整本次选择”；不提供假的“确认排序”，不自动转成前置或后置。 |

`plan.valid === false` 仍是执行门槛的权威依据。出现未知 issue 时保留原始原因的安全转义展示，不在 UI 临时发明新的执行规则；无效 plan 的兜底说明可为“当前计划不可执行，请检查目标与输入”。

“查看当前元素”不等于“完成删除确认”。如果动作会用元素编辑器替换当前预览弹窗，需先保存当前目标定位与预览返回上下文，或者本轮只做定位/关闭后打开，不悄悄丢失预览入口信息。编辑器对未知新快照的 stale 拒绝继续保留全部草稿，不能由帮助入口触发自动合并。

## 3. 工作台与单变量入口

保留现有检测状态，并增加独立的“当前计划”提示。检测来自 `matchResult`，计划来自 operations/issues，两者不可互换：“完全匹配”不等于无操作，“待应用”也不等于一定会写入。`renderInspector()` 现有“无需改变当前值”仅适合无保留 issue 的空操作计划。

单变量入口建议文案“预览此变量”，传入且只传入当前记录 `{app, profile, varIdx}`，复用 `showPreview('应用', …)`。批量勾选不应扩大这个入口的范围；它也不能自动改变勾选集合。提示可写“仅当前记录；其他方案依赖仍参与保护”。批量合并目标的计划可能与单变量计划不同，这是请求范围不同，不应在 UI 复用错误的单变量缓存冒充批量结果。

撤销按钮继续明确占位；不要因新增预览入口而把撤销重命名成“恢复输入”。“恢复编辑”属于原有会结束编辑会话的行为，不能成为每种 issue 的通用“修复”按钮。

## 4. 刷新、锚点与焦点身份规则

当前 `renderPreview()` 使用行序号保存 disclosure，并用“行序号 + relatedKey”恢复 token 焦点。它漏掉了所在区域；`actual:0` 等 key 本身还是当前快照的位置投影，不能当跨版本稳定身份。

1. **目标 identity**：使用现有 canonical target 的 `(scope, canonicalName)`，建议结构化序列化为 `JSON.stringify([scope, canonicalName])`。不要使用 app、数组下标、仅变量名或未经规范化的大小写。User/Path 与 System/Path 必须分离；多个应用的 User/Path 是一个目标。DOM id 用安全编码或本次弹窗内 key→id 映射，查询优先 dataset 比较，避免直接插入 CSS selector。
2. **锚点导航**：以目标 key 指向目标标题；按钮文案包含作用域和变量名，可附状态。按钮通过 `scrollIntoView` 导航后将 `tabindex=-1` 的目标标题聚焦。不要只滚动不移焦点，不要用 URL hash 污染外层导航。600px 下导航换行，不让整窗横向滚动。
3. **保存状态**：刷新前记录 activeElement 所属目标 key、控件类型、区域（actual/after/selected/summary/raw disclosure）、现有 relatedKey；同时按目标 key 保存每个原文 disclosure 的 open 状态。保留对话框 body 的 scrollTop；若结构变化明显，可用首个可见目标及视口内偏移恢复近似阅读位置。
4. **恢复 token 的限制**：同一冻结版本的纯展示重绘可用“目标 + 区域 + relatedKey”恢复；跨版本且快照/相关输入变更时，现有 `actual:N` / `selected:N` 不足以证明同一出现项。没有可验证的现有稳定身份映射，就回退到同目标标题，不用同值、同下标、唯一文本匹配猜身份。不能为了焦点创建删除资格或长期元素 ID。即使同 key 在两侧都存在，也只恢复原区域。
5. **逐级回退**：原控件仍存在→同目标标题→预览摘要/标题→关闭按钮。焦点原在 footer 且节点未替换时保持原位；若原确认按钮因刷新禁用，转到摘要。不要把焦点留在已移除 DOM/body，不自动跳到可能执行的确认按钮。关闭后优先恢复原触发按钮；触发按钮被重绘时通过原记录 identity 找新按钮，仍不存在则落到工作台标题或主预览入口。
6. **审阅约束**：刷新仅替换冻结 rows、推进 version 并使旧审阅失效。导航、展开原文、聚焦目标、公告朗读均不标记已审阅；确认点击发现变化时刷新并立即返回，不能顺便审阅或执行。之后仍需“审阅一次、确认一次”。不要改动全目标校验与同步提交之间无 await 的边界。

无障碍：摘要更新用一个短 `role=status` / polite live 区域，避免把整个 token 树设为 live；标题与按钮需可见文字，图标不承担状态。沿用现有 modal focus trap，确认过滤 hidden/disabled；Tab 进入各区域，方向键在 token 内移动。焦点 ring 与状态标签在绿灰配色下仍可辨识。新增导航不能吞掉编辑器现有方向键。尊重 reduced-motion，600px 下长路径断行或局部滚动，footer 可换行且不遮挡最后目标。

## 5. 五项关键验证（本报告未执行）

1. **部分应用矩阵**：构造安全新增并分别伴随 duplicate/shared/continuity 删除 issue。预览 After 和实际模拟结果只包含计划操作；确认可用；未解决记录保留原基线、输入和删除意图，历史标记部分完成。再次预览只有未解决删除且无 operations 时仍不声称完整完成，也不新增虚构修改历史。
2. **无操作与整批门槛**：完全无 operations、无 issue 时可确认成功选择，不能因“无变化”禁用；分别加入一个 conflict、stale 或 append 成员，即使其自身无变化也整批禁止执行，其他目标不发生写入。撤销始终仅说明、确认禁用。
3. **反复刷新与点击竞态**：预览打开后改变相关 Actual、选定输入或共享依赖，版本递增且只读刷新；第一次审阅点击零写入，第二次确认才可提交。若确认点击时再发现变化，当次只刷新返回；不相关目标变化不触发重新审阅。验证提交/历史严格使用同一被冻结计划。
4. **同名双作用域与焦点**：多个应用合并 User/Path，并另含 System/Path；分别展开原文、聚焦 after token 后刷新及重排目标。disclosure 不串目标，焦点不跳到 actual 或同下标不同元素；跨版本身份无证据时回退对应标题。关闭返回原单变量入口，不能落入后台失焦状态。
5. **600px 全键盘**：单变量入口→目标导航→原文→审阅→确认/取消全程可用；Tab/Shift+Tab 不逃离弹窗，Enter/Space 各只触发一次动作，Esc 关闭后返回合理位置。长名称/路径、多个保留说明、阻塞提示同时存在时不出现整窗横向溢出或 footer 遮挡，读屏可区分无值变更、删除保留、整批阻塞与待重新审阅。

本轮不修改 DemoPlan 算法、removalState、registry/V2 边界、三值 token 的业务含义或撤销能力；已有“安全操作已应用”通知在零操作且含 issue 时不够准确，可作为纯文案投影修正，但不能顺带改变提交路径。
