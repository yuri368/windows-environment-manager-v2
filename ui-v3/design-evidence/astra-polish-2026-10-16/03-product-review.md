## 结论

本轮方向成立，未发现需推翻布局或阻止整批改进的 P1。摘要先给结论，目标名称与作用域成为视觉主线，来源次行降低批量标题压力。工作台计划条只增加一行，明确的“查看对照”入口比整行隐式可点击更容易发现。建议收尾下列 P2 文案与诊断问题，随后以最终截图及行为回归验收。

## P2：需要收尾的具体项

1. **零操作、含删除保留时，按钮没有表达确认行为。** `renderPreview()` 使用“保留未解决意图”，但点击仍走确认流程，其他已解决记录可能提交成功选择；它容易被理解为另一种取消/保留草稿。建议改为“模拟确认当前计划”，保留现有“未解决删除继续保留”提示。无 issue 的“确认方案选择”正确，无需统一成禁用。

2. **旧摘要仍暗示元素编辑器能完成所有保护删除。** `planSummary()` 的“需在元素编辑器中确认”仍出现在详细预览及工作台结尾，与新 duplicate/shared/continuity 解释同时存在。shared 需要核对其他选定输入，continuity 也不是简单再确认即可恢复资格。建议替换为“未解决删除继续保留，请核对原因”；不改删除资格或提交行为。

3. **阻塞与更新同时出现时，视觉上缺少更新提示。** `reviewSummaryMarkup()` 让阻塞覆盖主标题合理，`previewVersionStatus` 也会播报更新；但后者是 sr-only，视觉用户只看到“本次暂不能应用”，除小号版本数字外看不到变化。可在阻塞摘要辅文追加“预览已更新至版本 N，请重新核对”。不要因此设置 reviewedVersion 或放开确认。

4. **已有诊断信息未充分展示。** stale 的 `issue.fields` 已由计划提供，当前只显示泛化的“作用域、模式与当前方案”；conflict 卡片有应用/方案列表，但统一的“批量合并”隐藏了各成员模式。建议针对实际存在的 fields 显示短字段名、对冲突成员显示模式，以帮助用户决定返回后检查哪里。未知 issue 可转义展示其 reason 作为兜底。无需推测共享保护者、增加解决按钮或重新计算计划。

前两项已即时消息给主执行者；后两项是低成本收尾建议。均为呈现层修改，不要求新增核心状态。

- **密度可接受。** 1360×900 预览中约一屏展示摘要、索引、一个完整短值目标及第二目标上部；600×640 时首屏展示结论、两个目标入口及首目标对照。长 Path 需要滚动属于内容本身。摘要和索引在 body 内，不持续侵占阅读高度；暂不建议加固定统计条、更多图例或默认折叠目标。

## 状态语义与交互判断

| 场景 | 当前实现判断 |
| --- | --- |
| 部分实际变更 + 删除保留 | 总摘要、按钮及完成通知区分部分完成；不宣称所有意图完成。准确。 |
| 只有删除保留、没有操作 | 标题明确当前值不变、删除待处理；通知也不再宣称已应用安全操作。仅按钮需按 P2-1 调整。 |
| 无操作、无 issue | 确认可记录方案选择，不新增变量修改历史；按钮保持可用。准确。 |
| invalid 或 append 限制 | 总确认禁用且明示整批不会执行；目标仍可定位/查看。实测 append 门槛正确。 |
| 撤销范围 | 总摘要和目标说明均承认不执行撤销，确认禁用。准确。 |
| 新版本待审阅 | 标题与按钮表达重新查看；原有 review → confirm 流程保留。阻塞同时发生时补视觉提示即可。 |
| 目标索引及刷新 | canonical 目标键区分作用域，跨版本 token 焦点回退同目标标题，原文开合按目标键恢复；代码方向正确。完整键盘回归由主执行者继续验证。 |

新工作台入口明确标为“查看方案预览 / 查看批量预览”，并复用现有确认范围。它没有声称“只预览此变量”，因此与当前实现相符，无需仅为了第 2 轮曾提出的单变量方案而更改任务范围。
