# 新增应用与方案分步填写

负责人在 UI 精修进行中指出：新增方案不应要求同时填写首个变量、作用域和模式。实施沿用现有 ConfigEditor session 草稿，只拆分界面输入步骤；createConfigEntry、ConfigFormat.errors、数据模型和导出规则保持不变。

- 新增应用：只填写应用名称 → 空应用草稿 → 新增方案，只填写方案名称 → 空方案草稿 → 按需新增变量。
- 现有应用中新增方案：只填写方案名称 → 空方案草稿 → 按需新增变量。
- 新增变量：只填写变量名即可创建（默认用户作用域/替换模式，默认值为空）；创建后填写值和候选。作用域/模式放在默认收起的“其他属性（可选）”。重名错误提供“调整作用域”，展开后聚焦到该字段，仍要求明确选择。
- 名称原文保留，立即检查重名、空白、NUL 和方案保留名。尚未完成下级内容的容器在左导航标记为草稿；主区显示当前容器，而不是首个变量的必填表单。
- 取消变量填写返回已命名的空方案，重新添加会恢复已输入的变量名。可切换应用、方案、原文/差异页后继续。仍沿用既有单个新增草稿与冲突处理，不新增并行空容器模型。
- 名称草稿仅在当前页面会话中保留，刷新不持久化；未完成草稿不进入导出，主区有明确说明。原配置仍可导出。
- 添加首个变量时，原回调一次校验并创建有效的应用/方案子树。没有占位变量，没有空容器的工作台/预览运行语义，没有修改完整配置校验。
