二、四项关键风险

P0：预览摘要不得混淆三个概念。

“目标数”“实际变更数”“尚未应用”具有不同语义：

目标数：本次计划涉及的目标。

实际变更数：按照现有规则计算的实际变更。

尚未应用：计划尚未执行的状态，而不是零操作或执行失败。

建议摘要直接读取既有计算结果，不在 UI 中重新推导。

P0：异常信息优先级不能降低。

正常摘要可以压缩，但以下状态仍须独立、清晰呈现：blocked、retained、partial、stale、零操作以及重新审阅要求。

尤其是版本失效后，必须继续阻止旧确认操作。不能因为视觉精简让用户误以为仍可直接执行。

P1：历史全宽展开不得破坏身份联动。

历史行的展开状态应绑定稳定记录标识，而非可见行索引。

Audit ID 定位、前后原文及滚动定位均须保持。筛选、重绘或展开其他记录后，不得出现详情错位。

P1：图例与原文必须可访问。

图例集中到弹窗内是合理的，但不能把重要风险说明藏进图例。

原文展开应支持键盘操作、长路径、空值、重复元素和 CRLF/CR/LF，不做隐式截断或归一化。

三、建议的验收重点

正常预览摘要与原有目标数、变更数一致

blocked、retained、partial、stale、零操作分别验证

预览刷新后旧确认失效，必须重新审阅

历史展开、折叠、Audit ID 定位及前后原文保持正确

桌面与 800px、600px 视口下无信息遮挡

四、实施裁决

同意 Codex 从干净基线推进 v3/phase2-preview-history-20261017。

本次无需重新设计 DemoPlan，也无需修改 refreshPreview、confirmPreview、版本绑定或历史数据结构。

与 AGY 的讨论仅作为视觉设计输入，现有安全契约优先于外部模型的美学意见。即便某个方案看起来更加简洁，也不得通过隐藏 blocked、retained 或尚未执行信息来实现。

最终提交请区分源码修改、自动测试、真实 Chrome 证据及未覆盖项目。

本阶段成功标准：正常状态阅读更快，异常状态依旧完整，历史详情更容易追踪，而且执行逻辑一个字也不用重写。 🔧
